# v0.2.0-beta.2 — candidate, not published

Experimental follow-up to v0.2.0-beta.1. This document prepares a release; it does
not announce availability. No tag or GitHub release has been created.

## Changes

- An accepted explicit OFF request persistently cancels older automatic ON
  recovery before device I/O, even if the request fails or is interrupted.
  Accepting OFF does not by itself confirm that the physical boiler is OFF.
- Explicit panel mode decisions are serialized with pending reads to avoid stale
  state racing the command.
- A deliberate OFF request may acquire known local control and immediately send
  OFF. Authorization is checked before each write; ownership and OFF require
  independent readbacks. Timed control, unknown modes and foreign sessions remain
  blocked. Neither write is blindly retried. This never enables a gas mode.
- Diagnostics include bounded, timestamped recent payloads for allowed read
  registers, without extra queries or identification/write frames. They contain
  telemetry and are not anonymous: review the complete file before sharing.

## Unchanged limits

Control and gas-DHW permissions default to disabled. Start in read-only mode.
The explicit local shutdown exception is not automatic startup/reconnect
recovery. No experimental helper-based automatic local takeover is included.
This is not a safety interlock or a guarantee of physical CAR position, flow,
continuous OFF state or recovery during a communications outage.
Compatibility remains limited to the tested 6-byte EXA protocol, not Magis Modbus.
These fixes do not establish the root cause of intermittent boiler timeouts.

## Validation and upgrade

See [validation and its limits](../validation.md) for the exact candidate checks.
No new physical device or outage testing is implied. HACS installation and
Hassfest/HACS Actions remain unverified.

Before any eventual upgrade, preserve the previous integration files and an HA
backup. Follow the normal installation instructions only after a release is
approved and published. No production update is part of this preparation.
